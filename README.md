# ROBOGEN RAG Chatbot

צ'אטבוט ארגוני מבוסס RAG לחברת רובוטיקה **בדיונית** בשם ROBOGEN. המערכת עונה על שאלות בעברית **על סמך 15 מסמכי החברה בלבד**, מציגה את המקורות שעליהם התבססה, ואומרת במפורש כשהמידע לא מופיע במסמכים ("המידע אינו מופיע במסמכי החברה"), במקום לנחש.

> כל התוכן במסמכים (החברה, המוצרים ATLAS / TITAN / SCOUT / CARGO והנתונים) בדיוני ונוצר לצורך פרויקט אקדמי.

## טכנולוגיות
| רכיב | בחירה |
|---|---|
| שפה / RAG | Python, LlamaIndex |
| Vector DB | ChromaDB (שמירה מקומית, מדד cosine) |
| Embeddings | `gemini-embedding-2`, ממד 768, עם קידומות משימה |
| מודל תשובות | `gemini-3.1-flash-lite`, temperature 0.1 |
| חיפוש מילות מפתח | BM25 (`BM25Retriever`) עם הסרת תחיליות בעברית |
| ממשק | Streamlit |

## התקנה
```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install --no-deps llama-index-retrievers-bm25
```
את החבילה `llama-index-retrievers-bm25` מתקינים בנפרד ועם `--no-deps`: היא דורשת `pystemmer<3`, ולגרסאות האלה אין wheel ל-Python 3.14 ב-Windows. ה-stemmer האנגלי ממילא לא בשימוש.

יש ליצור קובץ `.env` בתיקיית הפרויקט (הקובץ לא נכנס ל-git):
```
GEMINI_API_KEY=המפתח_שלכם
```
רק השם `GEMINI_API_KEY` נתמך. מפתח אפשר להוציא ב-[Google AI Studio](https://aistudio.google.com/).

**מאחורי סינון HTTPS (כמו NetFree):** החבילה `truststore` גורמת ל-Python להשתמש בתעודות של Windows, וזה כבר מוגדר ב-`config.py`.

## הרצה
```powershell
python src\check_setup.py        # בדיקה: המפתח נטען, קריאה בודדת ל-embedding ול-LLM
python src\ingest.py             # בניית האינדקס (Chroma + docstore) לתיקייה storage/
streamlit run src\app.py         # ממשק הצ'אט
```
מהטרמינל:
```bash
python src/retriever.py "מה זה RG-03?"                   # שליפה בלבד, בלי LLM
python src/rag.py "מה כושר הנשיאה של CARGO?" --show-prompt
python src/rag.py "מה כושר הנשיאה של CARGO?" "ומה לגבי SCOUT?" --chat   # שיחה עם זיכרון
python eval/run_eval.py                                     # בדיקות (ראו למטה)
```
ב-PowerShell 5.1 שאלה שמכילה `"` (למשל ק"ג) נשברת לכמה ארגומנטים. כדאי להשתמש ב-Git Bash או לכתוב ק״ג.

## ארכיטקטורה
```
Ingestion (פעם אחת)
  data/docs/*.md + metadata.json
    → SentenceSplitter (800/80) → 35 צ'אנקים
    → embedding עם קידומת "title: … | text: …" → ChromaDB (cosine)
    → docstore (לבניית BM25 בלי embeddings)

שאלה
  [זיכרון שיחה] אם יש היסטוריה: LLM מנסח את שאלת ההמשך כשאלה עצמאית (3 סבבים אחרונים)
    → Vector (top 10, קידומת "task: search result | query: …")
    + BM25   (top 10, הסרת תחיליות ה/ב/ל/ו/מ/ש/כ)
    → RRF (QueryFusionRetriever) → 6 צ'אנקים
    → פרומפט מערכת בעברית + קטעים ממוספרים → Gemini
    → תשובה + שורת "SOURCES: [1, 3]" → מקורות = המסמכים של הקטעים שצוינו
```
| קובץ | תפקיד |
|---|---|
| `src/config.py` | כל הפרמטרים במקום אחד |
| `src/embedding.py` | מודל ה-embedding וקידומות המשימה (משותף ל-ingestion ולשליפה) |
| `src/ingest.py` | טעינה, חלוקה, embeddings, שמירה |
| `src/retriever.py` | חיפוש היברידי |
| `src/rag.py` | זיכרון שיחה, פרומפט, תשובה, פענוח מקורות |
| `src/app.py` | ממשק Streamlit (RTL, מקורות, קטעים שנשלפו, "שיחה חדשה") |
| `eval/run_eval.py`, `eval/compare_runs.py` | בדיקות והשוואת לפני/אחרי |

**כללי התשובה (פרומפט המערכת):**
- לענות רק מהקטעים, ואם המידע חסר לומר זאת במפורש.
- בשאלת השוואה, לציין מי מוביל רק מבין הפריטים שהנתון שלהם מתועד.
- לא לקבל הנחה שגויה בשאלה.
- להעדיף מפרט מוצר על פני מסמך כללי.
- לענות בעברית, עם מונחים טכניים באנגלית.
- לציין את מספרי הקטעים שעליהם התבססה התשובה.

## בדיקות
השליפה נבדקת **בנפרד** מאיכות התשובה, על שני קבצי שאלות:
- `eval/questions.json`: 16 שאלות פיתוח.
- `eval/questions_holdout.json`: 12 שאלות שלא שימשו לכוונון. שאלה #2 שימשה לאבחון ומסומנת `used_for_diagnosis`.

**מדדי שליפה** (על 6 הקטעים שנשלפו):
- **Hit@6:** האם נשלף לפחות מסמך צפוי אחד.
- **MRR:** לפי המיקום של המסמך הנכון הראשון.
- **Recall@6:** איזה חלק מהמסמכים הצפויים נשלף.

**תשובות:** נבדקות ידנית, רק לתצורה הראשית.

### תוצאות (תצורה ראשית)
| הרצה | קובץ | Hit@6 | MRR | Recall@6 | תשובות נכונות |
|---|---|---|---|---|---|
| before | פיתוח (16) | 1.00 | 0.900 | 0.900 | 16/16 |
| after | פיתוח (16) | 1.00 | 0.856 | 0.889 | 16/16 |
| **final** | פיתוח (16) | **1.00** | **0.856** | **0.889** | **16/16** |
| before | holdout (12) | 1.00 | 0.773 | 0.939 | 9/12 |
| after | holdout (12) | 1.00 | 0.765 | 1.000 | 9/12 ‡ |
| **final** | holdout (12) | **1.00** | **0.765** | **1.000** | **11/12** § |

- **before:** 6 מועמדים מכל retriever.
- **after:** 10 מועמדים, וכלל השוואה בניסוח "אי אפשר לקבוע".
- **final:** ניסוח מרוכך של כלל ההשוואה ("מוביל מבין המתועדים").
- ‡ ב-after, holdout #2 ("איזה רובוט הכי מהיר?") קיבל את כל הנתונים הנכונים, אבל סירב לקבוע מוביל.
- § ב-final, holdout #2 עונה נכון: "מבין הרובוטים שנתוניהם מתועדים, CARGO הוא המהיר ביותר", ומציין שלגבי TITAN אין מידע. התשובה החלקית היחידה היא #10 (ראו מגבלות).

**מספר המועמדים לאיחוד (`CANDIDATES_TOP_K`), שליפה בלבד:**

| מועמדים | MRR פיתוח / holdout | Recall@6 פיתוח / holdout |
|---|---|---|
| 6 | 0.900 / 0.773 | 0.900 / 0.939 |
| 8 | 0.856 / 0.768 | 0.922 / 0.970 |
| **10 (נבחר)** | 0.856 / 0.765 | 0.889 / 1.000 |

עם 8, holdout #2 מקבל רק 2 מתוך 3 המפרטים הדרושים, ולכן נשאר 10.

**השוואת תצורות (after, MRR פיתוח / holdout):**

| תצורה | MRR |
|---|---|
| main (hybrid) | 0.856 / 0.765 |
| vector בלבד | 0.778 / 0.695 |
| BM25 בלבד | 0.724 / 0.700 |
| BM25 בלי הסרת תחיליות | 0.700 / 0.624 |
| בלי קידומות embedding | 0.883 / 0.806 |
| Query Expansion (3 שאילתות) | 0.856 / 0.742 |

כל הקבצים נמצאים ב-`eval/results_<tag>_retrieval.csv` וב-`eval/results_<tag>_answers.json`. להשוואה בין שתי הרצות: `python eval/compare_runs.py after final`.

## מגבלות וממצאים
- **מדגם קטן:** 16+12 שאלות ו-35 צ'אנקים. הבדלים של מקום אחד או שניים בכמה שאלות לא מובהקים.
- **הסרת תחיליות בעברית פשטנית:** היא מסירה לפעמים גם אותיות שורש ("מהיר" → "היר", "מהירות" → "ירות"), ולא מקשרת בין שם תואר לשם עצם.
- **קידומות embedding:** נשארו לפי התיעוד של Gemini, אף שבלעדיהן ה-MRR היה גבוה יותר בשני הקבצים.
- **השמטות ותוספות של המודל:**
  - holdout #10: חסר ש-Service & Maintenance מסייע בבדיקות, אף שהמסמך נשלף.
  - holdout #5: התשובה נכונה, אבל מוסיפה פירוט שלא נשאל (הגורמים שמשפיעים על זמן הפעולה).
- **רשימת המקורות** מבוססת על הקטעים שהמודל ציין. אם הפענוח נכשל, מוצגים כל המסמכים שנשלפו, עם הערה.
- **זיכרון שיחה:** תלוי באיכות הניסוח מחדש של ה-LLM, ומוסיף קריאת LLM לכל שאלת המשך. הבדיקות האוטומטיות רצות על שאלות בודדות בלבד.
- **שכבה חינמית של Gemini:** מוגבלת בקצב ול-1000 בקשות embedding ביום. כלי הבדיקה שומר וקטורי שאלות ב-cache (`eval/cache/`), כדי שהרצות חוזרות לא יצרכו מכסה.
